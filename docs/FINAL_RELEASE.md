# 최종 배포본 revision 4

2026-10-16. 이 문서와 `M2_N0_GUIDE.md`가 현재 M2·N0·N0-G0 규칙의 기준입니다. 이전 통합 기록과 seed201의 103조건 결과는 과거 버전의 기록이며 이번 결과와 합치지 않습니다.

## 이번 수정

1. **M2**: 이미 확정한 이번 주문의 정성적 근거를 전달합니다. 현재의 부재 표현(예: 백로그 없음/0)을 허용하고, 수량·통계·미래 주문 계획과 구분합니다. 현재 주문을 설명하는 표현과 미래 계획을 구별하는 문구 검사를 보완했습니다. 자연어의 사실 일치 여부를 완전히 판정하는 검사는 아닙니다.
2. **N0-G0**: 숫자 표기가 아니라 값의 적법성을 판정합니다. `10`, `10.0`, `1e1`은 같은 정수 행동으로 허용합니다. `10.5`, 문자열 `"10"`, 음수, 상한 초과, 불리언, 비유한 수는 거절합니다. 반올림·클리핑·재시도·대체 주문은 하지 않으며 실패한 주문은 확정하지 않습니다.
3. **실행기**: `Run-Experiment.ps1`도 `run_final.py`를 호출합니다. `-SafetyStock`은 필수이며 CMT의 Q_base 설명을 적용합니다. 기존 PowerShell 실행기가 다른 진입점을 호출하여 SS=0·Q_base 설명 없음으로 실행될 수 있던 경로를 수정했습니다.
4. **실제 응답에 따른 보완**: revision 3의 소규모 실행에서 `backlog is currently zero` 같은 부사·관계절 표현이 거절되는 오탐을 확인했습니다. revision 4에서 현재 부재 표현의 검사 문법을 보완하고 실제 원문을 회귀 검사에 추가했습니다. 통계·예측·미래 수량의 0을 허용하는 변경은 아닙니다.
5. **버전 구분**: 실행 메타데이터에 `implementation_revision=4`를 남깁니다. 기존 결과 폴더에 이어 쓰지 않습니다. 안전재고 10은 실행 설정이고 초기 실물 재고 0과 구분합니다.

공급망 물리 규칙, 비용식, C0~C3, T0~T4, M1·M3·M4, 수요 생성, 기존 A·D의 정의는 유지합니다. M3의 계획 근거는 분석 로그에만 보관하고 상류에 전달하지 않습니다. GitHub에 자동 게시하지 않습니다.

## 의사결정과 정보 경계

매기 소매점 → 도매점 → 유통업체 → 공장 순으로 한 흐름을 실행합니다.

1. 당기 수주 D와 하류 메시지를 수신합니다. 소매점 D는 고객 수요입니다.
2. 실제 도착량을 입고하고 기존 백로그와 당기 수주를 처리합니다.
3. I·B·P를 갱신합니다. 이때 `P_pre`는 이번 입고를 뺀 미입고 주문 잔량이며 이번 발주를 포함하지 않습니다.
4. 일반 CMT는 별도 30기 수주 이력으로 T 예측을 수행하고, OUT로 Q_base를 계산합니다. T의 30기 입력은 최종 주문 판단에 제공하는 C의 원자료 길이와 별개입니다.
5. LLM은 자기 C, 하류 M, 당기 Q_base를 종합해 최종 발주를 결정합니다. A·N0·N0-G0는 당기 별도 예측과 Q_base 없이 C0와 당기 D로 직접 결정합니다. D의 계산 방법은 기존 기준조건을 유지합니다.
6. 확정 주문을 상류 수주로 전달합니다. M2는 확정 후 별도 호출로 작성하는 설명이므로 원래 내부 추론을 그대로 복원하는 기록은 아닙니다.
7. `P_post = P_pre + Q_final`로 반영합니다. M1은 확정 상태를 환경 코드가 작성합니다. 그 밖의 메시지는 해당 규칙에 따라 생성·검사합니다.

`P`는 운송 중인 물량뿐 아니라 상류가 아직 출고하지 않은 주문도 포함합니다. 운송 중 물량의 도착은 실제 출고 후 2기입니다. `raw`는 반올림·범위 제한 등 수량 보정을 적용하기 전 값이며, 실제 실행 수량과 별도로 저장합니다.

## 재현 실행

Python 3.11 이상, 표준 라이브러리만 사용합니다. `OPENROUTER_API_KEY`는 환경변수로 설정하며 코드나 공유 ZIP에 넣지 않습니다. 최종 실험은 아래 진입점을 사용합니다.

```powershell
# 계획 확인: API 호출 없음
python run_final.py --conditions A N0 N0-G0 C0M0T2 C0M2T2 C3M2T2 C0M2T4 --seeds 201 --safety-stock 10 --evaluation-periods 10 --backend openrouter --workers 4 --budget-usd 2 --output results/final_r4_new_pilot --dry-run

# 오프라인 실행: 실제 LLM의 연구 성과로 해석하지 않음
python run_final.py --conditions A N0 N0-G0 C0M2T2 C3M2T2 C0M2T4 --seeds 201 --safety-stock 10 --evaluation-periods 2 --backend mock --output results/final_r4_mock_new

# 전체 조건은 목록을 명시적으로 선택. 아래는 계획 확인만 실행함.
$scmConditions = @((Get-Content ./configs/registered_conditions.json -Raw | ConvertFrom-Json).id)
python run_final.py --conditions $scmConditions --seeds 202 --safety-stock 10 --backend openrouter --workers 16 --budget-usd 20 --output results/final_r4_all105_seed202 --dry-run
```

실제로 호출하려면 `--dry-run`을 제거합니다. 등록 조건은 100 CMT + A + D_cost + D_bullwhip + N0 + N0-G0 = 105개입니다. 목적을 비교하려면 A/CMT/N0에 `--objective cost` 또는 `--objective bullwhip`를 지정합니다. D 두 조건의 목적은 각각 고정되어 있으므로 전체 목록에서는 목적 옵션을 생략합니다.

`--resume`은 동일 소스·설정의 중간 저장 상태에만 사용합니다. N0-G0의 실험적 중단은 최종 결과이므로 재개해도 다시 호출하지 않습니다. 인증·예산·모델 경로 오류는 실험적 중단과 구분하여 배치 오류로 남깁니다.

M2는 최종 파일럿에서 90번 생성 기회 중 90건이 전달됐고, 0건이 빈 메시지로 대체됐습니다. 앞선 revision 3에서는 90건 중 87건 전달·3건 대체였습니다. 두 실행은 LLM 응답과 이후 상태가 달라질 수 있으므로, 이 수치 차이만으로 개선의 인과효과를 주장하지 않습니다.

별도로 **revision 3의 M2 응답 95개를 고정한 재판정**에서는 기존 통과 87개 유지, 거절 5개 유지, 의도한 현재 부재 표현 3개만 거절→통과로 바뀌었습니다. 통과→거절과 예상 밖 판정 변화는 0개였습니다. 양수 수량을 적은 4개 응답은 계속 거절됐습니다. 이는 해당 문법 수정의 검증이며 모델 의미 해석 성능의 개선율은 아닙니다.

N0-G0에서 오류가 관측되지 않은 짧은 실행은 오류율이 0이라는 증거가 아닙니다. 정수 표기 수용, 비정상 주문 거절, 재시도·대체 없이 즉시 중단, 부분 결과 분리, 타 에피소드 계속 실행은 별도 오류 주입 검사로 확인했습니다.

실제 메시지에는 관측과 다른 백로그 주장이나 정보 주체 혼동이 남을 수 있습니다. 문구 검사 통과는 사실성 보증이 아닙니다. 비용·채찍효과 개선 검증은 별도 다중 seed 연구 실험으로 수행해야 합니다.
