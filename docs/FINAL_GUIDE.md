# FINAL: V1·V2와 안전재고/Q_base 개선의 결합

> 이 문서는 최초 FINAL 통합 설계를 설명합니다. 현재 정의·실행 방법·검증 범위는 [최종 배포본 revision 4](FINAL_RELEASE.md)과 [M2·N0·N0-G0 설명](M2_N0_GUIDE.md)을 우선합니다. 현재 등록은 105조건이며 N0·N0-G0에는 아래의 상세 공통 프롬프트·출처 라벨이 적용되지 않습니다.

## 무엇을 합쳤는가

| 구성 | 원래 의도 | FINAL 반영 |
|---|---|---|
| 실행 보조 스크립트 | SS와 Q_base 문장을 실행 시 변경 | 기존 스크립트 유지. `run_final.py`는 Q_base 설명을 적용하고 SS를 명시적으로 받음 |
| V1 | 주체·변수·시점·출처 정밀화, 주문 설명의 재전달 방지 | 공통 프롬프트, 호출별 감사 기록, `rationale`의 후속 입력 제외 |
| V2 | M3가 현재 발주량을 검토 없이 복사하지 않도록 상세 계획 지시 | LLM 자율 계획 + 내부 `planning_evidence`, 상류 전송은 정수 두 개 |
| 이번 보완 | 자기 정보를 하류 정보라고 사용하는 역방향 오류 | 두 방향의 귀속 오류 금지, 환경이 만든 `information_sources`, 핵심 주장에 출처 경로 표시 |

기존 V1과 V2는 원본 커밋 `4aa1e7bf109ee8811563ac9e20415bc29cd0edb1`에서 각각 만든 독립 버전입니다. V2가 V1의 누적 개선판은 아닙니다. FINAL은 처음으로 이를 결합한 새 처치이며, 결과를 기존 V1 또는 V2의 단순 추가 반복으로 분류하지 않습니다. V3의 전담 계획 Agent·후보 선택·계산기는 적용하지 않았습니다.

독립 버전의 원본 `v1_prompt_precision`과 `v2_m3_detailed_prompt` 및 기존 결과는 로컬에 보존하며 공유본에는 포함하지 않습니다. FINAL은 원본 및 기존 결과를 고치지 않고 별도 폴더에 만들었습니다.

## V1에 남아 있던 문제와 이번 통제

V1 감사 기록에는 공장 자신의 `C.current.I=363`을 distributor의 재고라고 설명한 사례 등이 있었습니다. 기존 지시문은 하류 정보를 자기 정보로 사용하지 말라는 방향이 강했고, 그 반대 방향의 귀속 오류가 남았습니다.

FINAL에서는 다음 규칙을 선택·최종 발주·메시지 작성에 공통 적용합니다.

1. `C`의 상태·이력·통계와 `Q_base`, `Q_final`, 자기 `P_post`의 소유자는 현재 판단 중인 역할입니다. 이를 하류 재고·백로그·미입고 주문량으로 바꿔 설명하지 않습니다.
2. 하류의 정량 상태를 주장하려면 **실제로 받은 M의 해당 값과 주체·시점**이 있어야 합니다. 정성적인 M2만 받고 자기 C의 숫자로 하류 재고를 채우지 않습니다.
3. `M`의 일인칭은 발신자를 가리킵니다. M4 등 재전달 문장의 명시적 주체는 그대로 보존하고, 발신자가 모든 문장의 주체라고 가정하지 않습니다. 주체가 불명확하면 미확인으로 남깁니다.
4. 자기 `C.current.P_pre`는 자기 발주 전 값이고, 하류 M1의 `M.P_post`는 하류 발주 후 값입니다. 주체와 시점 둘 다 다릅니다.
5. 비소매 에이전트의 자기 `C.current.D`는 바로 하류의 당기 실행 발주량과 같습니다. 이 거래 관계는 유지하되, **하류 자신의 수주 `M.D`와 같다는 뜻은 아닙니다.** 이 관계를 근거로 다른 I/B/P의 소유자까지 바꾸지 않습니다.

API 입력의 `information_sources.fields`에 코드가 다음과 같은 출처 표를 붙입니다. 아래는 형식 예시이고 새로 관측한 값은 아닙니다.

```json
{
  "source_path": "C.current.I",
  "owner_role": "factory",
  "period": 100,
  "phase": "after_fulfillment_before_current_order",
  "meaning": "Own on-hand inventory after current receipts and shipments."
}
```

숫자 상태는 원래 C/M 필드에 그대로 있으며 메타데이터에 복제하지 않습니다. 각 호출에 없는 필드의 관측값을 만들거나 타 에이전트의 내부 상태를 조회하지 않습니다. C3에서도 순서·개별 과거 관측을 추가하지 않습니다. 예측 호출에는 자기 30기 수주의 주체·기간만 표시하고 C/M을 넣지 않습니다. A에는 허용된 C/D의 출처만 추가합니다.

최종 판단 근거는 짧게 유지하면서 중요한 상태 주장에 역할과 실제 경로(예: `C.current.I`, `M.I`)를 적도록 지시합니다. M2의 송신 문장에는 숫자나 숫자가 들어간 출처 경로를 요구하지 않고 역할 단어로 주체를 표시하게 합니다.

**통제의 한계:** 출처 표는 코드로 확정하지만 LLM이 그 표를 항상 정확하게 읽는다고 보장할 수는 없습니다. 자연어 전체를 판정하는 검증기나 의미 오류 재시도는 이번에 추가하지 않았습니다. 따라서 “오류를 방지하도록 보완했다”와 “실험에서 오류가 사라졌다”를 구분해야 합니다. 텍스트 M의 사실 자체가 참인지도 이 메타데이터가 인증하지 않습니다.

## V1과 V2가 충돌했던 부분

독립 V2는 원본과 비교하기 위해 당기 `rationale`를 M3 입력으로 유지했습니다. 반면 V1은 그 설명이 사실처럼 재사용되는 것을 막으려고 후속 모델 입력에서 제외했습니다.

FINAL은 **V1의 비전달 원칙을 유지**합니다. 따라서 상세 M3 지시문에서도 `rationale`를 허용 입력이라고 설명하던 부분을 수정했습니다.

```text
최종 주문 입력: C + 받은 M + Q_base + information_sources
  → order_quantity + rationale
  → 수량 보정 후 Q_final 실행
  → rationale는 연구 기록에만 보존

메시지 작성 입력: C + 받은 M + Q_base + Q_final + P_post + information_sources
  → M3 내부 출력: plan_t_plus_1 + plan_t_plus_2 + planning_evidence
  → 상류 전달: plan_t_plus_1 + plan_t_plus_2
  → planning_evidence는 연구 기록에만 보존
```

A의 최종 판단은 기존대로 C0와 당기 D를 사용하며 Q_base/M을 만들지 않습니다. 상류 수신자에게 감사 근거·과거 주문 설명·별도 30기 예측 이력을 추가로 제공하지 않습니다. `rationale_audit`와 `stage_audit`도 다음 C에 들어가지 않습니다.

## M3가 어떻게 달라지는가

- 현재 주문을 확정한 뒤 **발주 후 상태**에서 t+1/t+2 자기 필요를 각각 판단합니다.
- 자기 I/B는 현재 발주만으로 변하지 않고, 자기 P_post에는 Q_final이 이미 포함됩니다.
- 수요와 입고에 관한 관측 사실 및 미래 가정을 구분합니다. P_post만으로 특정 기간의 입고량을 안다고 주장하지 않습니다.
- t+1 계획이 t+2의 상태에 미칠 영향을 고려하되, 계획 공식을 강제하거나 새 계산 도구·Agent를 만들지 않습니다.
- 현재 Q_final 또는 Q_base를 무조건 두 번 복사하지 말라고 지시합니다. 검토 결과 같은 값이면 허용하며 반복률을 낮추기 위해 값을 강제로 바꾸지 않습니다.
- 내부 응답은 두 계획 정수와 비공백 `planning_evidence`(최대 600자)입니다. 전체 출력 300토큰, 한 번의 공통 재시도 한도는 유지합니다.
- 실패하면 빈 메시지로 처리하고 이미 확정한 현재 발주는 유지합니다. 성공한 계획만 상류에 두 정수로 전달합니다. 계획을 다음 기 실제 발주로 강제하지 않습니다.

## 안전재고와 Q_base 문장

`run_final.py`를 사용하면 일반 CMT의 최종 주문 프롬프트에 전달본의 Q_base 문장을 추가합니다. A·D에는 그 문장을 붙이지 않습니다. 추가 문장과 그 한계는 [실행 보조 스크립트 설명](IMPROVEMENT_EXPERIMENTS.md#2-q_base-설명은-어디에-추가되는가)에 있습니다. 문구는 이전 처치와 비교할 수 있도록 보존했습니다.

안전재고는 임의의 고정값으로 바꾸지 않고 **`--safety-stock`을 필수 입력**으로 받습니다. 예를 들어 10을 입력하면 1~30기 준비기간부터 SS=10을 사용합니다. 초기 재고는 별도 기본값 0이며 `--initial-inventory`로 명시할 수 있습니다. SS가 다른 두 실행은 고객 수요 seed가 같아도 30기 말 상태가 다를 수 있습니다.

통합 후 `run_variant.py`, `run_qmean.py`, `run_all_settings.py`를 사용해도 이 폴더의 V1/V2/주체 구분 코드가 적용됩니다. 따라서 여기서 `run_variant.py --safety-stock 0`은 **옛 원본 baseline을 재현하는 명령이 아닙니다.** 옛 baseline은 보존한 기존 프로젝트에서 실행합니다. FINAL 안의 보조 스크립트는 SS/Q_base 추가 효과를 비교할 때 사용합니다.

## 파일과 결과

| 파일 | 변경 역할 |
|---|---|
| `run_final.py` | 통합 처치 진입점. 안전재고 명시 필수, Q_base 설명 적용 |
| `scm/prompts.py` | V1·V2 통합 및 양방향 주체·출처 규칙 |
| `scm/ownership.py` | 허용 입력에서만 정보 주체·시점·출처 메타데이터 생성 |
| `scm/harness.py` | 단계 감사, 입력 메타데이터 주입, 설명 비전달, M3 내부/전송 필드 분리 |
| `scm/provider.py` | 모의 응답이 M3의 planning_evidence 스키마를 만족하게 변경. 이후의 통신 오류 분류·N0-G0 호출별 복구 정책은 최신 설명서 참조 |
| `scm/variant.py`, `scm/runner.py` | FINAL ID·통합 원본·프롬프트 해시를 결과와 재개 서명에 포함 |

기본 `periods.json`, `api_calls.jsonl`, `summary.json`에 더해 처치 명세 `intervention_manifest.json`을 보존합니다. 실제 전송 입력과 같은 해시를 감사 기록에 넣습니다. 모델·API 경로, 물류엔진, 비용식, 예측식, C/M/T 등록 수준 및 수량 보정은 유지합니다. 동시 실행 상한은 현재 기본 프로젝트와 같은 16입니다. V1 실행용으로 별도 만든 18개 실행 지원이나 V3 기능까지 이식하지 않았습니다.

새 폴더에서 실행해야 합니다. 다른 버전의 manifest나 체크포인트 해시를 수동 수정하여 재개하지 마세요. 현재 `IncompleteRead`는 복구 가능한 호출 오류로 분류합니다. 일반 조건은 공통 재시도 한도 내에서 다시 시도하고, 소진되면 해당 단계의 대체 처리를 적용합니다. N0-G0는 재시도·대체 없이 해당 에피소드를 중단합니다. 자세한 내용은 [통신 오류 대응 안내](IMPROVEMENT_EXPERIMENTS.md#8-incompleteread-등-중단-시)와 [N0-G0 설명](M2_N0_GUIDE.md)을 확인하세요.

## 검증 및 다음 실험의 판단 기준

최초 통합 당시 오프라인 검사는 정보 경계, 당시 103조건의 mock 동작, 감사 설명 비전달, M3 내부 근거와 전송 숫자의 분리, 재개 충돌 차단 등을 확인했습니다. 과거 `final_integration.json`과 `verification-tests-final-combined.txt`는 로컬에 보존하며 공유본에는 포함하지 않습니다. 현재 배포본의 검증 범위와 결과는 [revision 4 기록](FINAL_RELEASE.md)을 확인하세요.

실제 LLM의 주체 혼동 감소는 동일한 저장 입력을 고정하여 다음을 따로 판정해야 합니다.

1. 하류→자기 귀속 오류와 자기→하류 귀속 오류.
2. 올바른 역할 이름을 붙였지만 다른 주체의 값을 가져온 경우.
3. 현재값·통계·발주 전후값을 혼동한 경우, 근거 없는 하류 수치를 만든 경우.
4. 정상 관측 인용과 명시적인 가정·전달받은 보고의 구분.

그 후 같은 seed·조건의 공급망 롤아웃에서 비용·서비스율·채찍효과와 토큰/지연/실패율을 비교합니다. 길어진 프롬프트와 출처 표로 토큰이 증가할 수 있습니다. 이 FINAL은 여러 개선을 결합했으므로 원본 대비 차이를 어느 한 문장만의 효과라고 주장하지 않습니다.
